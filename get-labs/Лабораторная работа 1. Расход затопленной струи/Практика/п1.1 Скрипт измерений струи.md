**Результат** — у вас есть отлаженный скрипт `jetMeasure.py`. Он проходит трубкой Пито поперёк струи заданное число точек, в каждой усредняет отсчёты АЦП, возвращает трубку в начало и сохраняет профиль в файл.
^intro

## Задание

### Что должно получиться

- [ ] На рабочем столе есть папка с вашим именем, в ней `jetFunctions.py`, `jetMover.py` и `jetMeasure.py`
- [ ] Вы умеете двигать трубку Пито скриптом `jetMover.py` и обнулять её положение
- [ ] Выводы GPIO 9, 10, 11 настроены под SPI, АЦП читает не нули
- [ ] `jetMeasure.py` снимает профиль и сохраняет файл, в котором каждой точке соответствует номер шага и средний отсчёт

### Как проверить

1. **Трубка возвращается.** После работы скрипта трубка стоит там же, где стояла до запуска.
2. **Отсчёты меняются.** При включённой воздуходувке отсчёты в середине файла заметно больше, чем по краям: трубка прошла через струю.

## Ход работы

### 1. Подготовить папку

1. Создайте на рабочем столе Raspberry Pi папку и назовите её своим именем.
2. Скопируйте в неё `jetFunctions.py` и `jetMover.py` из стартового набора.
3. Создайте в этой же папке пустой файл `jetMeasure.py`.

Прочитайте в [[т1.4 Экспериментальная установка струи#Датчик давления и АЦП|т1.4]] про особенности 24-битного АЦП: от них зависит, сколько отсчётов читать в точке.

### 2. Научиться двигать трубку

Запустите `jetMover.py` и введите `h`:

``` bash
python3 jetMover.py
```

>[!success] Должно получиться так
> ```
> Enter steps or command (h - help) > h
>
> Help for "Jet Mover":
>      50 - positive integer to step forward
>     -80 - negative integer to step backward
>       s - actual position relative to zero
>       z - set zero
>       q - exit
> ```

Сдвиньте трубку на 500 шагов вперёд и назад, посмотрите по поперечной линейке, в какую сторону она едет. Откройте `jetMover.py` и разберитесь, какие функции `jetFunctions.py` он вызывает и зачем нужен блок `finally`.

>[!warning] Не упирайте каретку в край
>Двигатель не знает, где кончается направляющая. Если каретка дошла до упора, а скрипт продолжает шагать, двигатель пропускает шаги, и положение трубки перестаёт совпадать со счётчиком. Двигайте трубку небольшими порциями и следите за ней глазами.

### 3. Настроить SPI и проверить АЦП

Настройте выводы под SPI командами `raspi-gpio`, как описано в [[о3 Raspberry Pi и АЦП#Настройка выводов под SPI|о3]]. Затем проверьте АЦП короткой программой в интерпретаторе:

``` python
import jetFunctions as j
j.initSpiAdc()
print(j.getAdc())
j.deinitSpiAdc()
```

Число должно быть около 209 000 и расти, если подуть в трубку Пито.

>[!warning] Если АЦП читает нули
>Запустите проверку из стартового набора: `python3 jetCheck.py`. Она покажет, есть ли SPI в системе, в каком режиме выводы GPIO9 и GPIO11 и какие байты приходят от датчика. Если приходят одни нули, запустите `python3 jetCheck.py bitbang`: она читает датчик без SPI. Если так датчик читается, он исправен, и дело в настройке выводов или проводе на ножке 21.
>
>Самая частая причина — после перезагрузки забыли `raspi-gpio set 9 a0` и `raspi-gpio set 11 a0`. Вторая — провод OUT воткнут в ножку 19 (MOSI) вместо 21 (MISO). Третья — у датчика и Raspberry Pi нет общей земли.

### 4. Написать скрипт измерений

Скрипт делает `count` точек. В каждой он читает `samples` отсчётов, усредняет их, записывает вместе с номером шага и сдвигает трубку на `stepsBetween` шагов. После сдвига он немного ждёт, чтобы датчик успел отпустить давление, см. [[т1.4 Экспериментальная установка струи#Датчик давления и АЦП|т1.4]]. После последней точки трубка возвращается назад на столько же шагов, сколько прошла.

>[!success] Должно получиться так
> ```python
> # jetMeasure.py
> import jetFunctions as j
>
> count = 60           # точек в профиле
> stepsBetween = 28    # шагов между точками: 28 шагов = 1 мм
> samples = 10         # отсчётов в одной точке, с паузой 0.05 с
>
> try:
>     # настроить двигатель и АЦП
>     # для каждой из count точек:
>     #     прочитать samples отсчётов, добавить в список среднее и номер шага
>     #     сдвинуть трубку на stepsBetween шагов вперёд и подождать 0.2 с
>     # вернуть трубку на count * stepsBetween шагов назад
>     # сохранить список в файл с говорящим именем
> finally:
>     # освободить АЦП и выводы двигателя
> ```

| Что нужно написать | Где подсмотреть |
| --- | --- |
| среднее из нескольких отсчётов | `sum(...) / samples`, `numpy.mean()` или `numpy.median()` — медиана не боится сбойных отсчётов |
| сохранение в файл | `np.savetxt(filename, rows, fmt=["%d", "%.1f"], header=...)`: строки заголовка начинаются с `#`, и `np.loadtxt` у программиста их сам пропустит. Так устроены файлы примера данных |

Скрипт собирается из кусков ниже. Расставьте их по местам в заготовке.

**Начало и конец.** Двигатель и АЦП включают один раз в начале, а выключают в блоке `finally`: он выполнится, даже если скрипт упал с ошибкой или его остановили `Ctrl+C`.

``` python
import time
import numpy as np
import jetFunctions as j

j.initSpiAdc()
j.initStepMotorGpio()
```

``` python
finally:
    j.deinitSpiAdc()
    j.deinitStepMotorGpio()
```

**Одна точка.** Прочитать `samples` отсчётов с паузой, чтобы АЦП успел выдать новое значение, и сохранить середину вместе с номером шага:

``` python
values = []
for k in range(samples):
    values.append(j.getAdc())
    time.sleep(0.05)
rows.append((i * stepsBetween, np.median(values)))
```

Перед циклом по точкам заведите пустой список `rows = []`, а сам цикл — `for i in range(count):`.

**Сдвиг и возврат.** После каждой точки трубку сдвигают и ждут, чтобы датчик успокоился. После всех точек возвращают назад на столько же шагов:

``` python
j.stepForward(stepsBetween)
time.sleep(0.2)
```

``` python
j.stepBackward(count * stepsBetween)
```

**Сохранение.** Два столбца, по строке на точку:

``` python
np.savetxt(filename, np.array(rows), fmt=["%d", "%.1f"], header="step adc")
```

Файл удобно сохранять двумя столбцами, «шаг» и «средний отсчёт», по строке на точку. Имя файла лучше передавать в скрипт параметром или задавать в начале скрипта: в п1.3 файлов будет восемь. Договоритесь о формате с программистом.

>[!tip] Сколько шагов и точек
>Ширина струи у сопла 15 мм, как диаметр сопла, а на 70 мм от сопла крылья профиля расходятся на 40–45 мм. Профиль надо снять с запасом, от чистого воздуха до чистого воздуха: у сопла 40 мм, на 30–50 мм — 60 мм, дальше — 75 мм. Точки удобно брать через 1 мм: при 0,036 мм на шаг это 28 шагов, и профиль — это 40–75 точек. АЦП выдаёт новое значение 10 раз в секунду, поэтому 10 отсчётов с паузой 0,05 с — это полсекунды на точку, вместе со сдвигом и паузой около секунды, и профиль снимается за 1–1,5 минуты. Читать сотни отсчётов подряд бессмысленно: это будут повторы одного числа.

### 5. Проверить скрипт

Поставьте трубку у сопла, на 0 мм по продольной шкале, и уведите её `jetMover.py` на 20 мм в сторону от центра струи. Включите воздуходувку в первом режиме, поставьте в скрипте `count = 40` и запустите его. Откройте получившийся файл.

>[!success] Должно получиться так
> ```
> 0 209191.0
> 28 209215.0
> ...
> 364 209385.5
> 392 220253.0
> 420 220416.0
> ...
> 1092 209245.0
> ```
> Отсчёты по краям — около 209 000, как без потока, посередине, на «столике» струи, — около 220 000. Если встретится число на порядок больше соседних, например 1 873 647, это сбой АЦП: такие точки бывают, не пугайтесь, программист их отбросит.

Скрипт готов к калибровке и измерениям.
