**Результат** — измеритель надёжно ловит хлопок у входа в трубу: на записи видны сигналы обоих микрофонов, сдвинутые друг относительно друга, а запись сохраняется на Raspberry Pi.
^intro

## Задание

### Что должно получиться

- [ ] SPI включён, выводы GPIO 9, 10 и 11 настроены под SPI — 1 балл
- [ ] Порог триггера подобран так, что запись не запускается от шума, но запускается от хлопка — 1 балл
- [ ] Написан `soundMeasure.py`: по имени опыта он сохраняет записи обоих микрофонов в `sound/data/<имя>_0.txt` и `<имя>_1.txt` и показывает их на графике — 2 балла

### Как проверить

1. **Два сигнала.** На записи сначала отходит от фона сигнал микрофона 0, ближнего к открытому концу, потом микрофона 1.
2. **Задержка правдоподобна.** Сигнал микрофона 1 отходит от фона примерно на 840 отсчётов позже: 1,158 м / 345 м/с ≈ 3,36 мс, а один отсчёт — 4 мкс.

## Ход работы

Измеритель — плата Raspberry Pi Pico 2 с уже записанной программой, как она устроена — в [[т4.5 Экспериментальная установка трубы#Измеритель на Pico|т4.5]]. Программировать Pico не нужно: общаться с ним помогают готовые функции из `soundPico.py`, а скрипт записи вы пишете сами.

### 1. Подготовить Raspberry Pi

1. **Включите SPI.** Если на этой Raspberry Pi SPI ещё не включали, выполните `sudo raspi-config` → Interface Options → SPI → Enable и перезагрузитесь, если попросит. Проверьте, что появилось устройство:

``` bash
ls /dev/spidev0.0
```

2. **Настройте выводы.** Обмен с Pico идёт в обе стороны, поэтому нужны все три вывода шины, см. [[о3 Raspberry Pi и АЦП#Настройка выводов под SPI|о3]]:

``` bash
raspi-gpio set 9 a0
raspi-gpio set 10 a0
raspi-gpio set 11 a0
raspi-gpio get 9-11
```

У GPIO9, 10, 11 должно быть написано `SPI0_MISO`, `SPI0_MOSI`, `SPI0_SCLK`. После перезагрузки повторите. GPIO8 трогать не нужно: им управляют функции `soundPico.py`.

3. **Положите файлы.** Скопируйте `soundPico.py` из стартового набора в `sound/scripts` репозитория команды на Raspberry Pi, создайте там же пустой `soundMeasure.py` и папку `sound/data`. Запускать скрипт будете из корня репозитория.

### 2. Написать скрипт записи

В `soundPico.py` три функции, как у АЦП в других работах:

| Функция | Что делает |
| --- | --- |
| `initPico()` | открывает SPI и выбирает Pico, один раз в начале |
| `capture(threshold)` | даёт Pico команду ждать хлопка, а после записи возвращает два массива отсчётов: микрофон 0 и микрофон 1 |
| `deinitPico()` | закрывает SPI, один раз в конце |

Скрипт собирается из четырёх кусков.

**Имя опыта** берут из командной строки, чтобы для каждого опыта не править скрипт: `python3 sound/scripts/soundMeasure.py air1`.

``` python
import sys
import numpy as np
import matplotlib.pyplot as plt
import soundPico as pico

name = sys.argv[1]          # air1, breath1, ...
dataPath = "sound/data/"
threshold = 20              # порог запуска, коды АЦП от фона
```

**Запись.** Связь с Pico закрывают в блоке `finally`: он выполнится, даже если запись не удалась или скрипт остановили `Ctrl+C`.

``` python
pico.initPico()
try:
    mic0, mic1 = pico.capture(threshold)
finally:
    pico.deinitPico()
```

**Сохранение** — по файлу на микрофон, целыми числами, по отсчёту в строке:

``` python
np.savetxt(dataPath + name + "_0.txt", mic0, fmt="%d")
```

Второй файл, `_1.txt` для `mic1`, допишите сами.

**График** обоих микрофонов на одних осях, чтобы сразу увидеть, удалась ли запись. Его тоже допишите сами: `plt.plot()` для каждого микрофона, подпись оси, легенда, `plt.show()`.

### 3. Пробная запись

1. Запустите скрипт: `python3 sound/scripts/soundMeasure.py test1`. В терминале появится ответ Pico `armed` и надпись `Хлопайте!`, на Pico загорится **зелёный** светодиод: он ждёт хлопка.
2. Хлопните в ладоши у открытого конца трубы — со стороны микрофона 0. Хлопайте в воздухе и не задевайте трубу: удар по металлу тоже даёт сигнал, но это волна в стали, а не в воздухе.
3. Загорится **синий**: Pico записал сигналы и передаёт их. Передача длится около 14 секунд, потом скрипт сохранит `test1_0.txt` и `test1_1.txt` и покажет график.
4. Если запись запускается сама, без хлопка, поднимите порог `threshold`, например до 30. Если за 15 секунд хлопок запись не запустил, загорится **красный**, а в терминале будет ответ с ошибкой — хлопните громче или опустите порог. Порог — это отклонение микрофона 0 от фонового уровня в кодах АЦП, по умолчанию 20.

>Синяя и оранжевая линии на графике скрипта — микрофоны 0 и 1, запись `air1` из примера данных. Сначала спокойный фон. Около отсчёта 300 сигнал микрофона 0 отходит от фона — сначала вниз, — а примерно через 835 отсчётов, около отсчёта 1130, так же отходит микрофон 1. Триггер сработал на отсчёте 512, когда отклонение достигло порога, — позже настоящего начала импульса, поэтому в записи и сохраняется предыстория. Постоянные уровни каналов разные, около 870 и 960, это нормально.

Если оба канала — ровные линии без хлопка, хлопните громче или ближе к открытому концу трубы. Если запись обрезана на 0 или 4095, хлопок слишком громкий: хлопните тише или чуть дальше от трубы.

Отправьте `soundMeasure.py` и `soundPico.py` в `sound/scripts` репозитория команды.
