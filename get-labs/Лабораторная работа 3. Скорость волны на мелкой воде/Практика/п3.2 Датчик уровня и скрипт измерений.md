**Результат** — датчик уровня проверен мультиметром, а скрипт `waveMeasure.py` умеет два режима: записать заданное время сразу или дождаться открытия дверцы и записать после него. Частота измерений выше 100 Гц и печатается после каждой записи.
^intro

## Задание

### Что должно получиться

- [ ] Напряжение на выходе датчика уровня меняется с уровнем воды
- [ ] Скрипт пишет отсчёты АЦП заданное число секунд и сохраняет их в файл с длительностью записи
- [ ] Скрипт умеет ждать открытия дверцы перед записью
- [ ] Средняя частота дискретизации выше 100 Гц

### Как проверить

1. **Мультиметр.** Когда в кювету доливают воду, напряжение на выходе датчика меняется плавно и в одну сторону.
2. **Частота.** Скрипт печатает число отсчётов и частоту, и частота больше 100 Гц, на установке около 1800 Гц.

## Ход работы

### 1. Проверить датчик уровня

Датчик уровня уже собран на макетной плате по варианту 2 из [[т3.2 Датчик уровня воды#Вариант 2. Переменное напряжение|т3.2]] и питается от блока ±5 В. Его выход подключён к разъёму блока 5 В платы get-adc. Подключите мультиметр к выходу датчика и, доливая воду в кювету, проверьте, что напряжение меняется. Запишите, растёт оно с уровнем или падает.

### 2. Прочитать АЦП

Подготовьте папку, как в лр5: создайте на рабочем столе папку с вашим именем и скопируйте в неё `mcp3021_driver.py` из своего репозитория `get` — драйвер АЦП с занятия по АЦП. Создайте в той же папке пустой `waveMeasure.py`.

Выведите шину I2C на выводы: `raspi-gpio set 2 a0` и `raspi-gpio set 3 a0`. Затем проверьте АЦП в интерпретаторе: при неподвижной воде отсчёты почти не меняются, при доливании воды меняются.

``` python
from mcp3021_driver import MCP3021
adc = MCP3021(5.0)
print(adc.get_number())
adc.deinit()
```

### 3. Собрать скрипт

Скрипт собирается из готовых кусков:

| Кусок | Откуда взять |
| --- | --- |
| ожидание открытия дверцы | ваш скрипт из [[п3.1 Датчик открытия дверцы#3. Написать ожидание\|п3.1]] |
| цикл измерений заданное число секунд | [[о3 Raspberry Pi и АЦП#Цикл измерений по времени\|о3]], вместо `getAdc()` — `adc.get_number()` |
| печать числа отсчётов и частоты | там же, в о3 |
| сохранение в файл с длительностью и датой | функция `save()` из [[о3 Raspberry Pi и АЦП#Формат файла с данными\|о3]], первую строку замените на `- Wave Lab` |

Цикл измерений для MCP3021 выглядит так:

``` python
samples = []
start = time.time()
while time.time() - start < duration:
    samples.append(adc.get_number())
finish = time.time()
```

В цикле — только чтение и `append`, без печати и без `time.sleep()`, см. [[т3.4 Экспериментальная установка кюветы#Что ограничивает частоту|т3.4]].

>[!success] Должно получиться так
> ```python
> # waveMeasure.py
> import time
> import RPi.GPIO as GPIO
> from mcp3021_driver import MCP3021
>
> duration = 15            # секунд записи
> waitDoor = True          # False — для калибровки
> filename = "data/wave 60 mm.txt"
>
> # функция save() из о3
>
> # создать объект АЦП, настроить вход дверцы GPIO15, как в п3.1
> try:
>     # если waitDoor: ждать открытия дверцы, как в п3.1
>     # цикл измерений
>     # напечатать число отсчётов и частоту
>     # сохранить: save(samples, start, finish, filename)
> finally:
>     adc.deinit()
>     GPIO.cleanup()
> ```

Папку `data` создайте заранее: `mkdir -p data`.

### 4. Измерить частоту

Запустите скрипт без ожидания дверцы на 10 секунд и посмотрите частоту.

>[!success] Должно получиться так
> ```
> Отсчётов: 18400, частота 1840 Гц
> ```

Если частота заметно ниже, ищите, что тормозит цикл. Попробуйте ради опыта добавить в цикл `print()` каждого отсчёта и посмотрите, во сколько раз упадёт частота: это ответ на контрольный вопрос 10 и хороший материал для отчёта.

Отправьте `waveMeasure.py` и `mcp3021_driver.py` в `wave/scripts` репозитория команды.
