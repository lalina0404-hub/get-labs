Во всех работах данные снимает скрипт на Python, запущенный на Raspberry Pi. В работе со светом скрипт управляет камерой, а в остальных в цикле читает отсчёты АЦП, складывает их в список и после измерений сохраняет в файл. Как подключить внешний АЦП, как устроено чтение отсчёта и в каком виде сохранять данные, чтобы программисту было удобно их обрабатывать?

## Внешний АЦП MCP3201

Внешние АЦП подключают к Raspberry Pi по SPI или I2C. В работе со струёй датчик давления с 24-битным АЦП [[HX710B]] читается по SPI, см. [[т1.4 Экспериментальная установка струи#Датчик давления и АЦП|т1.4]]. В работе с пульсовой волной датчик подключён к 10-битному АЦП MCP3021 платы get-adc и читается по I2C вашим драйвером с занятия по АЦП, см. [[т5.3 Экспериментальная установка тонометра#АЦП и компьютер|т5.3]]. Как устроено чтение по [[SPI#^def|SPI]], разберём на примере самого простого из таких АЦП — 12-битного [[MCP3201]].

| Вывод MCP3201 | Назначение | Куда подключён |
| --- | --- | --- |
| 8 VDD, 1 V_REF | питание и опорное напряжение | 5 V (ножка 2) |
| 7 CLK | тактовый сигнал SPI | GPIO11, SPI0_SCLK (ножка 23) |
| 6 D_OUT | данные от АЦП | GPIO9, SPI0_MISO (ножка 21) |
| 5 CSN | выбор микросхемы | GPIO8, SPI0_CE0 (ножка 24) |
| 4 V_SS, 3 IN− | земля | GND (ножка 6) |
| 2 IN+ | измеряемый сигнал | выход датчика |

Схема подключения и даташит лежат в разделе документации: [[Схема подключения MCP3201.pdf]], [[MCP3201 Datasheet.pdf]].

### Настройка выводов под SPI

По умолчанию GPIO9, 10 и 11 работают как обычные входы-выходы. Чтобы ими управлял аппаратный SPI, их переводят в альтернативную функцию 0 командами в терминале Raspberry Pi:

``` bash
raspi-gpio get
raspi-gpio set 9 a0
raspi-gpio set 10 a0
raspi-gpio set 11 a0
raspi-gpio get
```

Первая и последняя команды печатают состояние выводов: после настройки у GPIO9–11 должно быть написано `func=SPI0_...`. Настройка сбрасывается при перезагрузке, повторяйте её после каждого включения.

>[!warning] Если команды нет
>В новых версиях Raspberry Pi OS утилиту `raspi-gpio` заменила `pinctrl`. Команды те же по смыслу: `pinctrl set 9 a0` и так далее. Надёжнее один раз включить SPI в `sudo raspi-config` → Interface Options → SPI: тогда выводы настраиваются сами при загрузке.

### Чтение одного отсчёта

Функции для работы с АЦП по SPI даются готовыми в стартовом наборе, например `jetFunctions.py` в работе со струёй. Чтобы снимать данные, достаточно знать три функции:

| Функция | Что делает | Когда вызывать |
| --- | --- | --- |
| `initSpiAdc()` | открывает связь с АЦП | один раз в начале скрипта |
| `getAdc()` | возвращает одно измерение — целое число | столько раз, сколько нужно измерений |
| `deinitSpiAdc()` | закрывает связь | один раз в конце, в блоке `finally` |

``` python
import jetFunctions as j

j.initSpiAdc()
print(j.getAdc())        # например, 209147
j.deinitSpiAdc()
```

Число от `getAdc()` — это отсчёт АЦП. Его диапазон зависит от разрядности: у 12-битного АЦП от 0 до 4095, у 24-битного датчика струи без потока около 209 000. В физическую величину отсчёт переводит калибровка, см. [[о4 Калибровка и аппроксимация#^intro|о4]]. Этого достаточно для работы. Ниже — для тех, кому интересно, что происходит внутри `getAdc()`, на примере MCP3201.

### Что внутри getAdc()

``` python
def getAdc():
    adcResponse = spi.xfer2([0, 0])
    return ((adcResponse[0] & 0x1F) << 8 | adcResponse[1]) >> 1
```

**Первая строка — обмен байтами.** По [[SPI#^def|SPI]] Raspberry Pi и АЦП обмениваются байтами одновременно, как двое, которые передают друг другу записки из рук в руки: отдаёшь одну и тут же получаешь одну. Нам нечего сообщать АЦП, поэтому мы отдаём два нулевых байта, `[0, 0]`, а взамен получаем два байта с результатом. `adcResponse` — список из двух чисел от 0 до 255, например `[207, 50]`.

**Вторая строка — собрать из двух байтов одно число.** Результат АЦП занимает 12 бит, а пришло 16 бит, два байта по 8. АЦП раскладывает их так:

| Бит | 1–2 | 3 | 4–8 | 9–15 | 16 |
| --- | --- | --- | --- | --- | --- |
| Что в нём | мусор: АЦП ещё измеряет | всегда 0 | старшие 5 бит результата | младшие 7 бит результата | лишний, повтор |
| Где | первый байт | первый байт | первый байт | второй байт | второй байт |

Значит, нужно выкинуть из первого байта три первых бита, приклеить к оставшимся второй байт и отрезать один лишний бит в конце. Это делают четыре операции над двоичными числами:

| Операция | Что делает | Пример |
| --- | --- | --- |
| `a & 0x1F` | «маска»: оставляет 5 младших бит, остальные обнуляет. `0x1F` — это `00011111` | `11001111 & 00011111 = 00001111` |
| `a << 8` | сдвигает биты на 8 позиций влево, справа дописывает нули — освобождает место для второго байта | `00001111` → `00001111 00000000` |
| `a \| b` | «склеивает»: ставит 1 везде, где 1 хотя бы у одного из чисел | `00001111 00000000 \| 00110010` = `00001111 00110010` |
| `a >> 1` | сдвигает на 1 позицию вправо — последний бит выпадает | `…0011 0010` → `…0001 1001` |

Пройдём весь путь на примере, где пришло `[207, 50]`:

| Шаг | В двоичном виде | Число |
| --- | --- | ---: |
| первый байт | `11001111` | 207 |
| второй байт | `00110010` | 50 |
| `207 & 0x1F` — убрали мусор | `00001111` | 15 |
| `15 << 8` — сдвинули влево | `00001111 00000000` | 3840 |
| `3840 \| 50` — приклеили второй байт | `00001111 00110010` | 3890 |
| `3890 >> 1` — отрезали лишний бит | `00000111 10011001` | **1945** |

Получилось 12-битное число 1945, это и есть отсчёт АЦП.

>[!info] У датчика струи то же самое
>Датчик давления в работе со струёй выдаёт 24 бита — три байта. Его `getAdc()` склеивает их тем же способом: первый байт сдвигается на 16 позиций, второй на 8, третий остаётся как есть, и всё соединяется операцией `|`. Мусорных и лишних бит там нет, поэтому маска и сдвиг вправо не нужны.

>[!info] Дополнительно
>Опорное напряжение MCP3201 в наших схемах 5 В, поэтому один отсчёт соответствует 5 / 4096 ≈ 1,22 мВ. Напряжение в вольтах программисту обычно не нужно: калибровка связывает отсчёты прямо с давлением, минуя вольты.

## Цикл измерений по времени

Если нужно измерять заданное число секунд, цикл сравнивает текущее время с моментом начала:

``` python
import time

samples = []
initSpiAdc()
start = time.time()

while time.time() - start < duration:
    samples.append(getAdc())

finish = time.time()
deinitSpiAdc()
```

В теле цикла только чтение АЦП и `append`. Печать каждого отсчёта в терминал замедлит цикл в десятки раз. По `start`, `finish` и длине списка считается средняя частота дискретизации:

``` python
print("Отсчётов: %d, частота %.0f Гц" % (len(samples), len(samples) / (finish - start)))
```

Её полезно записать в отчёт: она определяет, насколько подробно записан сигнал.

## Формат файла с данными

Удобно, когда все файлы работы устроены одинаково: несколько строк заголовка с описанием опыта, пустая строка и столбец отсчётов. Такой файл удобно и просмотреть человеку в текстовом редакторе, и прочитать скриптом. Этот формат использован в примерах данных стартовых наборов:

```
- Blood Lab
- Date: 2021-10-28 17:26:39
- Duration: 60.00 s

1945
1947
...
```

Функции сохранения и чтения в таком формате:

``` python
import time
import numpy as np

def save(samples, start, finish, filename):
    with open(filename, "w") as outfile:
        outfile.write("- Blood Lab\n")
        outfile.write("- Date: {}\n".format(time.strftime("%Y-%m-%d %H:%M:%S", time.localtime(start))))
        outfile.write("- Duration: {:.2f} s\n\n".format(finish - start))
        np.savetxt(outfile, np.array(samples), fmt="%d")

def read(filename):
    with open(filename) as f:
        lines = f.readlines()
    duration = float(lines[2].split()[2])
    samples = np.asarray(lines[4:], dtype=int)
    return samples, duration, len(samples)
```

`read()` возвращает отсчёты, длительность записи и их число. Время каждого отсчёта программист восстанавливает как `np.linspace(0, duration, count)`: считается, что отсчёты шли равномерно. Время отдельных отсчётов в файл не пишут, поэтому это допущение. Оно нарушается, если цикл измерений время от времени тормозит: в нём есть печать или запись в файл, или Raspberry Pi отвлекается на другие программы. Тогда часть отсчётов на самом деле разделена бо́льшими промежутками, и время на графике немного сдвигается.

>[!warning] В стартовых наборах этих функций может не быть
>В текущих стартовых наборах файлы `*Functions.py` содержат только работу с АЦП, а сохранение в файл экспериментатор пишет сам. Функции выше можно взять за основу. Главное — договориться с программистом о формате до первых измерений.

Имя файла лучше задавать явно и по смыслу: `40 mmHg.txt`, `rest.txt`, `20 mm.txt`. Тогда программист сразу видит, что в каком файле, а скрипт обработки читает файлы по понятным именам.

## Если АЦП читает нули

1. Проверить, что выводы настроены под SPI: `raspi-gpio get`.
2. Проверить питание АЦП и датчика мультиметром.
3. Проверить провода по схеме: перепутанные CLK и D_OUT дают нули или мусор.
4. Убедиться, что сигнал на входе меняется: подуть в трубку датчика или сжать грушу тонометра и посмотреть, меняются ли отсчёты.
