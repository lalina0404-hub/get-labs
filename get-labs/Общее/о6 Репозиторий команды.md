Результаты работы сдаются не на флешке и не в чате, а в общий публичный репозиторий команды на GitHub. Так преподаватель видит всё сразу, а команда не теряет файлы между занятиями. Как разложить файлы, чтобы в репозитории было легко разобраться?
^intro

## Одна папка на работу

Все файлы, относящиеся к лабораторной работе, складываются в отдельную папку общего открытого для просмотра репозитория команды:

| Работа | Папка |
| --- | --- |
| [[лр1 Расход затопленной струи#^intro\|лр1]] | `jet` |
| [[лр2 Свет, цвет и альбедо#^intro\|лр2]] | `light` |
| [[лр3 Скорость волны на поверхности воды#^intro\|лр3]] | `wave` |
| [[лр4 Скорость звука в газовой среде#^intro\|лр4]] | `sound` |
| [[лр5 Визуализация пульсовой волны#^intro\|лр5]] | `blood` |

Внутри папки удобно разделить отчёт, скрипты, данные и графики:

```
team-repo
├── jet
│   ├── report
│   │   ├── jet-report.odt
│   │   └── jet-presentation.pdf
│   ├── scripts
│   │   ├── jetFunctions.py
│   │   ├── jetMover.py
│   │   ├── jetMeasure.py
│   │   └── jetProcessing.py
│   ├── data
│   │   ├── calibration
│   │   │   ├── 00 Pa.txt
│   │   │   └── 45 Pa.txt
│   │   ├── 00 mm.txt
│   │   └── ...
│   └── plots
│       ├── pressure-calibration.png
│       └── ...
├── light
└── ...
```

Скрипт обработки читает данные из `data` и сохраняет графики в `plots`. Пути к папкам лучше задать переменными в начале скрипта:

``` python
dataPath = "jet/data/"
plotsPath = "jet/plots/"
```

## Отправка изменений

Каждый в команде отправляет свою часть сам, сразу как она готова:

``` bash
git pull
git add --all
git commit -m "Калибровка давления, лр1"
git push
```

`git pull` перед работой забирает то, что уже отправили соседи. Если два человека правили один и тот же файл, git попросит разрешить конфликт. Чтобы этого не случалось, договоритесь, кто какие файлы меняет: данные — экспериментатор, скрипт обработки и графики — программист, отчёт — руководитель.

>[!warning] Не забудьте данные
>Без файлов с данными нельзя проверить ни обработку, ни графики. Сырые данные сдаются всегда, даже если получились неудачными: неудачный опыт, честно описанный в отчёте, лучше пропавшего.
